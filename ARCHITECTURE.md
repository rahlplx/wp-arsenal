## Core Design Patterns

### 1. Shared-Library + Context Manager

All scripts import `WPConnection` from `wp_connect.py`. There is no duplication of SSH setup, retry logic, or SFTP management.

```python
with WPConnection(args) as wp:
    out = wp.ssh("ls /var/www/html")
    rows = wp.db("SELECT * FROM wp_options LIMIT 5")
```

The `__enter__` method calls `connect()` (with 3-attempt retry + keepalive); `__exit__` closes both SFTP and SSH.

### 2. CLI-first, Config-fallback

`add_connection_args()` defines a standard flag set. `config_loader.load_config()` merges YAML values after parse, with CLI flags always winning. This runs transparently inside `WPConnection.__init__`.

### 3. AuditResult Accumulator

Every audit script creates an `AuditResult("script-name")`, calls `.add(severity, category, detail, path)`, and calls `.print_summary()` at the end. Optional `--json` flag outputs `result.to_dict()`.

### 4. Severity Model

| Level | Meaning |
|---|---|
| CRITICAL | Confirmed malware / active exploitation evidence |
| HIGH | Significant risk (exposed credential files, rogue admin) |
| MEDIUM | Configuration weakness, recently modified files |
| LOW | Minor information disclosure |
| INFO | Hardening applied, no issue |

## Data Flow

```text
User/CI
  │
  ▼
CLI args (--host, --user, --wp-path, ...)
  │
  ▼
config_loader.load_config()   ← merges config/config.yaml
  │
  ▼
WPConnection(args)
  ├── SSH (paramiko) ──────────────────────────────────┐
  │   ├── wp.ssh(cmd)         → stdout as str           │
  │   ├── wp.ssh2(cmd)        → (stdout, stderr)        │ Remote server
  │   └── wp.db(sql)          → base64→decode→mysql     │
  ├── SFTP (lifecycle-managed) ──────────────────────── │
  │   ├── wp.sftp_read(path)  → bytes                   │
  │   ├── wp.sftp_write(path, bytes) → bool             │
  │   └── wp.sftp_chmod(path, mode) → bool              │
  └── HTTP probes via curl-over-SSH ────────────────────┘
      ├── wp.http_code(url)   → '200' / '403' (str)
      └── wp.http_body(url)   → response body
  │
  ▼
AuditResult
  └── print_summary() / JSON output
```

## Security Architecture

### SQL Injection Prevention

| Mechanism | Applied Where |
|---|---|
| `WPConnection.db()` base64-encodes every query | All `wp.db()` calls — shell never sees SQL literals |
| `WPConnection.sql_escape(value)` | Arbitrary string values in SQL |
| `WPConnection.sql_slug(value)` | Theme slugs, usernames, identifiers — strict `[A-Za-z0-9_.-]` |
| `MYSQL_PWD=` env var | All mysqldump/mysql calls — password invisible to `ps` |

### Shell Injection Prevention

| Mechanism | Applied Where |
|---|---|
| `shlex.quote(url)` | All `curl` calls in `http_code()` and `http_body()` |
| `WP_PAT=shlex.quote(pattern) grep -E "$WP_PAT"` | Malware grep patterns with `$_` regex metacharacters |
| `shlex.quote()` for all shell-interpolated paths | `wp.wp_path`, `wp.wp(rel)` in `find`, `ls`, `cp` and `wp_exists()`/`wp_readable()` — migrated from manual single-quoting to `shlex.quote()` to correctly handle paths containing `'`. (Note: audit item S-4 tracks the separate `mysqldump` credential-injection issue, not this path-quoting concern.) |

### PHP MU-Plugin Security Model

| Plugin | Mechanism |
|---|---|
| `admin-guard.php` | IP prefix match vs `WP_ARSENAL_TRUSTED_CIDRS`; blocks wp-admin/wp-login |
| `rate-limiter.php` | WP transients: N failures → lockout transient (separate key so window reset doesn't lift it) |
| `honeypot.php` | HMAC-derived token (`hash_hmac(sha256, hourly-epoch, secret)`) — raw secret never in HTML |
| `ip-blocker.php` | `str_starts_with` prefix match against `WP_ARSENAL_BLOCKED_CIDRS` |
| `security-headers.php` | Standard HTTP security headers; HSTS only when HTTPS detected |

| Package | Pinned Constraint | Current Status |
